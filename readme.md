# comfont

AviUtl2の標準テキストに、文字分類・Unicode範囲ごとのフォントと装飾を適用するRust製プラグインです。
フォント、サイズ、ベースライン、字送り、垂直・水平比率をプロファイルとして保存できます。

## インストール

AviUtl2 v2.1.1以降が必要です。配布の *.au2pkg.zip をプレビュー画面へドラッグ＆ドロップし、再起動してください。

- Plugin/comfont.aux2 — プロファイル編集・描画用モジュール・旧版本文の復元メニュー
- Script/合成フォント.anm2 — テキストオブジェクトに付けるプロファイル指定

暫定仕様の「合成フォントテキスト」「合成フォント字幕」「合成フォント名前表示」のobjectは新しいパッケージには同梱しません。
既存プロジェクト用にリポジトリ内のソースとLua APIは維持しています。

## 標準テキストとanm2で使う

1. 「設定 → プラグイン設定 → 合成フォント…」でプロファイルを作り、保存します。
2. AviUtl2を再起動してanm2の選択肢を読み込みます。
3. 標準テキストに本文を入力し、アニメーション効果「合成フォント」を追加します。
4. anm2の「プロファイル選択」プルダウンでプロファイルを選びます。

anm2からaux2内のcompositefontモジュールへ自動接続し、DirectWriteで生成した画像をobj.putpixeldataで適用します。
**テキストオブジェクトの本文・設定値を書き換えません。** そのまま本文を編集できます。効果を無効化・削除するか「無装飾」を選ぶと元の描画になります。
合成フォントは、本文を加工する他のフィルターより前へ置いてください。既に加工された画像を再描画で置き換えるためです。

保存時にプロファイル一覧からanm2の静的select定義を生成します。公開Lua APIでは起動中にプルダウンの項目定義を更新できないため、追加・削除・名前変更後は再起動が必要です。既存プロファイルの補正値だけの変更は約1秒後に反映します。
選択IDは名前から生成し、並べ替えや別プロファイルの追加で変化しません。IDまたは表示名が衝突する保存は拒否します。
削除・名前変更で選択先がなくなった場合は元の描画を維持します。名前変更後は選択し直してください。
区切り文字・改行・バックスラッシュを含む名前はプルダウンの表示用に置換します。

旧anm2の名前入力は「旧版のプロファイル指定」に残しています。空でない場合はプルダウンより優先します。「無装飾」は旧指定があっても無装飾になります。
試験版の本文ラッパーを使った既存プロジェクトは、テキスト欄を右クリックして「プラグイン → 合成フォント → 元の本文に戻す」を一度実行してください。新規の組み込み操作は不要です。

現在の自動描画は横書き・標準文字装飾・静止本文を対象とした試験実装です。縦書き、影・縁取り、表示速度、個別オブジェクト、スクロール、Lua本文、未対応タグ、結合文字・複雑な文字組み・絵文字シーケンスはAviUtl2の元の描画を維持します。
字形単位で描くため、カーニング・合字を含めた標準テキストとの完全一致は保証しません。画像は最大4096×4096、サイズは1～512、本文は64 KiBまでです。

SDK調査と実機の確認状況は [検証記録](docs/validation.md) を参照してください。

anm2の確定仕様は [anm2仕様](docs/anm2-spec.md) を参照してください。

## プロファイル編集

組み込みのdefaultは名前の変更・削除ができません。その中の範囲・分類は削除できます。「新規…」でプロファイルを追加してください。

| 項目 | 内容 |
|---|---|
| フォント | 範囲・分類へ適用するフォント。空欄は変更なし |
| 単位 | サイズ・ベースライン・字送りを%またはpxで指定 |
| サイズ | %では100が等倍、pxでは絶対サイズ |
| ベース | 正の値で文字を上へ移動 |
| 字送り | 正の値で文字間を広げる |
| 垂直・水平 (%) | 100が等倍。単位にかかわらず常に% |

サイズ・垂直・水平比率は0より大きい値が必要です。単位変更では数値を自動換算しません。
フォントが空欄の行は候補から除外され、その行の補正も適用しません。

### Unicode範囲

[Unicode 17.0.0のブロック](https://www.unicode.org/Public/17.0.0/ucd/Blocks.txt)を343種類登録しています。漢字拡張A～J、かな拡張、各言語の文字・記号・絵文字などをブロック単位で選ぶと、開始・終了へ値を入力します。
egui版では漢字・ひらがな・カタカナ・欧文（Basic Latin）・半角／全角をスクロールしない上部に固定し、その他のブロックを独立してスクロールします。検索欄には日本語名・公式英語名・範囲内のコードポイント（例: U+3042）を入力できます。
値は16進数で手動編集でき、U+・0xの接頭辞も使えます。「範囲を追加」で登録し、選択した範囲の値を変更して「適用」を押すと更新します。

両端を含む範囲です。補助平面にも対応し、上限はU+10FFFFです。開始が終了より大きい場合、サロゲートU+D800～U+DFFFを端点とする場合、上限外の値は登録できません。
範囲がサロゲート領域をまたぐことはできますが、サロゲートそのものは文字として解決しません。

- カスタム範囲は既存の7分類より優先します。一覧では7分類の後に表示されます。
- 重複する場合は、カスタム範囲一覧の上から最初に一致したものを採用します。
- 一致した範囲のフォントが空欄なら無装飾です。下位の範囲・分類には移りません。
- ↑ / ↓でカスタム範囲同士の順序を変更できます。
- 既存分類は候補を上から確認し、グリフを持つ最初のフォントを使います。
- 本文中の対応済み書式タグは、カスタム範囲の設定より優先します。

### 削除と復元

−で固定分類行・追加候補行・カスタム範囲を削除できます。固定分類の先頭を削除すると、次の候補が先頭になります。
最後の候補も削除すると分類は無効です。すべて削除したプロファイルは無装飾になり、保存・再読み込みでも削除状態を維持します。

固定分類を戻す場合は、プリセットの「分類を復元: …」を選んで「分類を復元」を押します。
+は選択分類の候補追加、カスタム範囲ではコピー追加です。コピーは同じ範囲なので開始・終了や優先順を調整してください。

旧プロファイルは同じ7分類・候補順のまま読めます。追加フィールドはcustom_rangesとdisabled_classesです。
新フィールドを保存したファイルは旧バージョンのcomfontでは読めません。

### 保存とプレビュー

「適用」は画面上のモデルとプレビューへ反映し、「保存」・「OK」はファイルへ保存します。「キャンセル」は最後の保存後の変更を破棄します。
プロファイルはAviUtl2のアプリケーションデータ内のcompositefont/profiles.jsonへ保存し、モジュールが約1秒間隔で変更を確認します。

プレビューは本体と同じ範囲・フォールバック解決処理と、AviUtl2のFontManagerにあるDirectWriteフォント・文字計測を使います。
設定変更時に画像を更新し、ウィンドウ再描画にはキャッシュを使います。
字形単位の比較用なので、カーニング・合字、本文書式タグ、オブジェクト配置や表示速度まで含む完全な確認にはAviUtl2本体のプレビューを使用してください。

### egui試験画面

cargo build -p compositefont-editor-plugin --features egui-uiでビルドすると、「合成フォント (egui 試験版)…」設定メニューが追加されます。
左側にプロファイル、右上にプレビュー、その下にフォント一覧と編集欄を配置したダークテーマの画面です。
新規プロファイルは左ペイン上部の「＋」から作成します。プロファイル名はダブルクリックまたは編集アイコンでインライン編集できます（defaultの名前は固定）。
「追加」はプリセット／カスタム範囲ダイアログを開き、「コピー」は選択範囲・候補のフォントと補正値を複製します。削除した分類の復元も追加ダイアログから行えます。
セクション見出しは明るいグレーの帯で区切ります。個別フォント設定の「✔適用」は見出し右側に配置します。
補正値は2列で、左にサイズ・ベースライン・字送り、右に垂直・水平を配置します。各項目にFormat Size・Swap Vert・Format Letter Spacing・Height・Arrow Rangeのアイコンを表示します。
左ペインの縦・横の区切り線は表示しません。
フォント一覧はShiftクリックで始点から終点まで選択、Ctrlクリックで追加・解除します。通常クリックで複数選択を解除し、その行を選択します。複数選択時の個別設定見出しは「(nつ選択)」です。変更した項目だけを選択行へ適用し、未変更のフォント・補正値は維持します。表示値は最後に選んだ行の値です。単位を変更した場合はサイズ・ベースライン・字送りも表示中の値をまとめて適用し、自動換算はしません。範囲の開始・終了編集は1行選択時だけ行えます。削除・コピー・移動も選択行を対象にします。
数値欄をホバーしてホイールで調整できます。通常は1、Shiftは0.1、Ctrlは10ずつ。数値欄上ではページをスクロールしません。サイズ・垂直・水平の下限は0.1です。
フォント一覧の行は罫線で区切ります。説明は項目のホバーに応じて下部へ表示し、離れると通常の状態表示に戻ります。
フォント欄は直接入力と検索可能な一覧選択に対応します。プルダウンを開くと検索欄へフォーカスします。候補一覧は「変更なし」を含め最大5行とし、件数が少ない場合は行数に合わせて縮めます。検索語の変更時は一覧を先頭へ戻します。検索欄のクリックでは閉じず、候補の選択・外側のクリック・Escapeで閉じます。プルダウンの左端は入力欄に揃え、現在の検索結果の高さとデスクトップの作業領域（タスクバーを除く）の空きに応じて上下を自動選択します。下側に収まれば下へ、足りなければ上へ開きます。上下とも足りない場合は空きが広い側で表示行数を減らします。候補一覧は独立したウィンドウで、設定画面の外側にも表示できます。設定画面の移動や検索語の変更でも再判定します。「✔適用」でプレビューへ反映します。

検索画面は親画面とは独立した描画イベントで更新します。位置・サイズは変更時だけ更新し、初回は描画完了後に表示します。プレビューのテクスチャを再利用し、ホバーの明暗アニメーションを無効にしています。DPI対応は設定画面のUIスレッドに限定します。
操作・OSイベント・必要な再描画要求に応じて更新し、動画フレームからUIを呼び出しません。
フォント一覧は開いた時に取得し、プレビュー画像は内容が変わった時に更新します。UI用日本語フォントはYu Gothic UI Regular（YuGothM.ttcのface 1）を優先し、代替にMeiryo UI（meiryo.ttcのface 2）を使用します。
操作ボタンにはGoogleの[Material Icons](https://developers.google.com/fonts/docs/material_icons)、補正値にはMaterial Symbolsを使用しています。補正値用は5種類だけを含む静的フォントを埋め込みます。[フォントの出典・加工内容](resource/material-icons/README.md)を記録し、[Apache-2.0ライセンス](resource/material-icons/LICENSE.txt)を同梱します。

実機のIME・DPI・繰り返し開閉・負荷比較が完了するまでは、通常ビルドの既定画面はWin32版です。
採用条件と未確認項目は [検証記録](docs/validation.md) にまとめています。

## 追加フォント

システムへインストールしていないフォントも利用できます。

1. AviUtl2のアプリケーションデータにある`compositefont/fonts`へフォントファイルを置きます。
2. 合成フォントエディターで`保存`を押します。
3. 新しいフォントが配置された旨のメッセージを確認し、AviUtl2を再起動します。

`compositefont/fonts`がない場合は作成してください。エディターで一度`保存`を押すことでも作成されます。

対応形式はTTF、OTF、TTC、OTCです。サブフォルダー内も読み取ります。通常インストールでは
`C:\ProgramData\aviutl2\compositefont\fonts`、ポータブル構成ではAviUtl2本体横の
`data\compositefont\fonts`が目安です。

`保存`を押すと、新しいファイルだけをAviUtl2の`Font/compositefont`へコピーします。同名ファイルは
上書きしません。別のサブフォルダーへ同名ファイルを複数置かないでください。フォントの利用条件は
各フォントのライセンスに従ってください。

## 文字種

| 文字種 | 主な対象 |
|---|---|
| 漢字 | CJK漢字、部首、画、`々`など |
| かな | ひらがな、結合濁点・半濁点 |
| カナ | 全角・半角カタカナ、`ー`、半角濁点・半濁点 |
| 記号 | 句読点、記号、絵文字、`・`など |
| 欧文 | 半角ASCIIの英字 |
| 数字 | 半角・全角を含むUnicodeの数値文字 |
| その他 | 空白、全角英字、アクセント付き欧文、その他の言語など |

## 現在の制限

- `decorate`と`decorate_layout`は、本文中にある次のAviUtl2基本書式タグを解析し、タグの表記を
  維持したまま可視文字だけへ合成フォントを適用します。

  - `<#[文字色][,影・縁色]>`、リセットの`<#>`
  - `<s[サイズ][,フォント][,BIS][,縁取りサイズ]>`、リセットの`<s>`
  - `<@[フォント][,0～6/BIS]>`、リセットの`<@>`
  - 太字・斜体・取り消し線を追加または解除する`<@+BIS>`、`<@-BIS>`

  `B`は太字、`I`は斜体、`S`は取り消し線です。複数指定する場合は`BI`のように続けて記述します。
  色は6桁RGBか、標準プリセット名の`white`、`red`、`yellow`、`green`、`aqua`、`blue`、
  `magenta`、`black`に対応します。SDKから名前を取得できないカスタム色プリセットは未対応です。
- 書式の優先順位は、常に「本文中の入力タグ、comfontプロファイル、テキストオブジェクトの既定値」
  の順です。優先順位は属性ごとに判定し、複数属性を持つタグでも、実際に指定されたフィールドだけが
  プロファイルより優先されます。入力タグのリセット後は、該当属性へのプロファイル適用を再開します。
- 上記以外のタグ、未知のタグ、引数や構文が不正なタグが本文に1つでもある場合は、安全のため本文全体を
  加工せず返します。表示速度、待機、表示クリア、座標移動、ルビ、Lua制御スクリプト、コメントなどは
  対応していません。閉じていない半角の`<`も同様です。全角の`＜`は通常の文字として使えます。
- Luaが実行時に生成した動的文字列は、自動では合成フォント化されません。動的文字列へ適用する場合は、
  生成後の最終文字列をLua側から明示的に`decorate`または`decorate_layout`へ渡してください。
- `decorate`または`decorate_layout`へ存在しないプロファイル名、不正な補正値、制御文字と衝突する
  フォント名を渡した場合は、表示を壊さないよう元の本文を返します。`decorate_layout`の補正量は`0`に
  なります。
- プロファイル名はAviUtl2標準のフォント一覧には表示されません。anm2の「プロファイル選択」またはLuaの引数で指定してください。
- 新しく追加した実フォントの反映にはAviUtl2の再起動が必要です。
- 混在フォントの上端見切れ補正は、行頭がDirectWriteで等幅と判定されるフォントかつ2文字以上の行に
  適用します。比例フォントはカーニングや合字を壊さないよう、通常の文字種別変換だけを行います。

## 制御スクリプトから使う

標準テキストオブジェクトのLua制御スクリプトから直接呼び出すこともできます。テキスト欄へ
次のLua制御文字を記述します。`obj.mes()`はテキストオブジェクト内で使用してください。

```lua
<?
local compositefont = obj.module("compositefont")
local font, size, _, _, _, _, _, spacing = obj.getfont()
local text = compositefont.decorate_layout(
    "任意のテキスト ABC123", "subtitle", size, spacing, font
)
obj.mes(text)
?>
```

### `decorate_layout(text, profile?, base_font_size?, base_char_spacing?, base_font_family?)`

文字種ごとの設定をAviUtl2制御文字へ変換した文字列を返す推奨APIです。等幅の先頭フォントと
後続フォントで文字の高さが異なる場合は、行頭1文字のサイズと縦横比を一時的に補正して上側の描画領域を確保します。
行全体を`<p>`で囲まず、字送りも次の1文字で相殺するため、本文の配置と横幅は変わりません。
対応済みの基本書式タグを含む場合も、入力タグの書式を優先し、可視文字だけを変換します。
互換性のため第2戻り値も残していますが、常に`0`であり座標補正は不要です。従来の
「合成フォントテキスト」と「合成フォント字幕」、旧版の本文連携スクリプトはこのAPIを使用します。

### `decorate(text, profile?, base_font_size?, base_char_spacing?)`

文字種ごとの設定をAviUtl2制御文字へ変換した文字列を返します。`profile`を省略すると`default`を
使用します。サイズと字間を渡すと、ベースラインと字送りを現在のテキスト設定に合わせて計算します。
対応済みの基本書式タグを含む場合も、入力タグの書式を優先し、可視文字だけを変換します。
既存スクリプトとの互換用で、混在フォントの上端見切れ補正は行いません。

### `resolve(character, profile?, base_font_size?)`

1個のUnicodeスカラー値に適用する設定を8個の値で返します。

```lua
local font, size_ratio, baseline, tracking,
      vertical, horizontal, category, rule_id =
    compositefont.resolve("漢", "subtitle", 64)
```

戻り値は、フォント名、サイズ倍率、ベースライン量、字送り量、垂直倍率、水平倍率、文字種名、
使用したルールIDの順です。ベースライン量と字送り量は基準サイズを`1`とする比率、垂直・水平は
倍率です。空文字、複数のUnicodeスカラー値、存在しないプロファイルはエラーになります。

### その他の関数

- `resolve_codepoint(codepoint, profile?, base_font_size?)` — Unicodeコードポイントで`resolve`と同じ結果を取得
- `profile_names()` — 現在のプロファイル名一覧を取得
- `profile_name(selection, saved_label?)` — anm2選択IDと保存ラベルから名前を取得。不一致はnil
- `render_text(text, profile, font, size, spacing, line_spacing, color, align, bold, italic)` — anm2用の画像を生成。未対応はnil、成功時はdata・width・heightを持つ所有権付きuserdata
- `api_version()` — 現在のスクリプトモジュールAPIバージョン`11`を取得

`px`単位の行を`resolve`する場合は`base_font_size`を渡してください。省略すると、フォントと垂直・
水平比率だけが適用対象になります。

### ネイティブ文字run適用

現在のAviUtl2 SDKには、テキストのレイアウト直前に文字runを差し替える公開コールバックが
ありません。そのため、anm2はDirectWriteの画像再描画を行い、Luaから直接使う場合は`compositefont.decorate`でAviUtl2制御文字を生成します。

将来、SDKに次のような境界が追加された場合は、プロファイル形式や文字分類を変えず、適用部分だけを
ネイティブバックエンドへ交換します。次のシグネチャは必要な情報を示す概念例であり、確定APIでは
ありません。

```text
resolve_text_runs(text, base_format) -> [
  { range, font_family, size_ratio, baseline, tracking, vertical, horizontal }
]
```

```text
profiles.json + text + FontManagerのグリフ情報
                    |
                    v
             resolve_text_runs
                    |
             ResolvedTextRun[]
                    |
          +---------+----------+
          |                    |
          v                    v
 ControlTagBackend       NativeSdkBackend
 （現在のdecorate）       （将来実装）
```

### 共通文字run

バックエンドから独立した`ResolvedTextRun`と文字run解決処理は、将来の交換に備えて現行コードにも
実装されています。各runは次の情報を持ちます。

- 元テキスト上のUTF-8バイト範囲
- DirectWriteやWindows API用のUTF-16コード単位範囲
- フォント、サイズ、ベースライン、字送り、垂直比率、水平比率をまとめた補正値
- 補正を持たず元の文字を維持する改行run

文字分類、フォールバック、グリフの有無の判定はこの共通層で行い、隣接する同じ補正値は1つのrunへ
まとめます。既存Lua経路はrunを`<@>`、`<s>`、`<gw>`、`<tw>`、`<th>`、`<p>`へ
変換する`ControlTagBackend`を使います。anm2の画像描画は同じ分類・範囲・フォント解決を字形単位で使います。
ホストの文字レイアウトへrunを渡す`NativeSdkBackend`は未実装です。

### SDK対応後の移行

SDKに文字run解決コールバックが追加された場合は、次の順序で対応します。

1. SDKが使うrangeの単位を確認し、UTF-8またはUTF-16範囲へ対応させる。
2. `NativeSdkBackend`を追加し、共通の補正値をSDKの構造体へ変換する。
3. プロファイル選択とコールバック登録だけをAviUtl2との連携層へ追加する。
4. ネイティブ経路では制御文字を生成せず、元テキストとrun配列をホストへ渡す。
5. `decorate`は既存プロジェクトとPSDToolKit2向けの互換APIとして残す。

文字分類、フォールバック順、`profiles.json`、エディターの保存形式は維持し、SDK固有の型は共通層へ
持ち込みません。これにより、AviUtl2側のDirectWriteレイアウト、キャッシュ、縦書き、装飾を保った
まま合成フォントを適用できる構成を目指します。

### 既存制御文字との共存

現行版は対応済みの基本書式タグと可視文字をトークン化し、入力タグの書式状態と合成フォントの補正を
属性ごとに合成します。入力タグは元の表記を維持し、合成フォントがrunごとに補正タグをリセットしても、
入力側の有効な書式と効果範囲が変わらないよう必要な状態を復元します。対応外、未知、不正なタグが1つでも
ある場合は、部分的な変換を行わず本文全体をそのまま返します。

### 未確定事項

- 標準テキストオブジェクトと合成フォントプロファイルを関連付けるSDK上の方法
- コールバックのrange単位、寿命、呼び出しスレッドなどの契約
- run解決結果のキャッシュ。必要性を計測してから導入し、導入する場合はプロファイル設定の更新状態、
  本文、基準フォントサイズ、基準字間をキーの候補とする

## 開発

```powershell
cargo fmt --all -- --check
cargo test --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
au2 release
```

`au2 release`の成果物は`release/`へ生成されます。
