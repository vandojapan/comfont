# comfont 0.3.3 β

AviUtl2のテキストに、文字の種類やUnicode範囲ごとに異なるフォント・サイズ・字間などを適用するプラグインです。通常のテキストは本文を変更せず、AviUtl2標準の描画で表示します。

## 導入と基本的な使い方

AviUtl2 **v2.1.14以降**が必要です。

1. 配布パッケージ（`*.au2pkg.zip`）をAviUtl2のプレビュー画面へドラッグ＆ドロップし、AviUtl2を再起動します。
2. 「設定 → プラグイン設定 → 合成フォント (β)…」を開き、`default` を編集するか、新しいプロファイルを作って「保存」を押します。
3. 通常のテキストオブジェクトにアニメーション効果「描画@comfont」を追加します。
4. 効果の「comfont::プロファイル」に、保存したプロファイル名を入力します。初期値は `default` です。

設定画面の「適用」は編集内容をプレビューに反映します。動画へ反映するには「保存」または「保存して閉じる」を押してください。保存した設定は描画時に約1秒間隔で読み直されます。

## プロファイルの設定

「追加」から文字分類・Unicodeプリセットを選ぶか、開始・終了コードポイントを16進数で入力して範囲を作れます。プリセットは名前やコードポイントで検索できます。範囲が重なる場合はカスタム範囲を優先し、同じ条件では一覧で先にある設定を使います。フォント候補は上から順に字形の有無を調べます。「変更なし」の行に到達した場合は、その行のパラメータを使い、後続のフォント候補へは進みません。

「よく使う範囲」の「絵文字（Unicode 18.0）」は、Unicode.orgの絵文字・構成文字を154範囲・1行で設定できます。対象範囲の網羅性は、選択フォントでの全絵文字の表示を保証するものではありません。[絵文字の設定と制約](docs/emoji.md)と[対象コードポイントの出典](resource/unicode/README.md#絵文字unicode-180)を参照してください。

数字・`#`・`*` は `1️⃣` のようなキーキャップの構成だけを絵文字として扱います。単独の数字や、利用できるキーキャップ字形のない場合は、下位の一致する数字範囲などへ渡します。

キーキャップは下位フォントを使う場合も、書記素全体をcomfontで描画して合成します。標準描画へ戻ることで結合記号が崩れる問題は、`beta-emoji-keycap-render-fix` パッケージで修正しています。

`beta-emoji-keycap-svg-fix` はTwitter Color Emojiに内蔵された12種類のキーキャップSVGを直接取得し、既存のComfont Emoji Markerで配置します。通常の数字には影響せず、VS16省略形にも対応します。設定プレビューと映像出力で同じ字形を使い、単独文字の `🔟` も合成対象です。

| 項目 | 設定内容 |
|---|---|
| フォント | 名前を入力するか、検索して選択。候補名は各書体で表示します。空欄（変更なし）なら元のフォントを引き継ぎ、他の有効なパラメータを適用します。 |
| サイズ | `%` または `px`。100%が等倍です。 |
| ベースライン | `%` または `px`。正の値で上へ移動します。 |
| 字送り | `%` または `px`。正の値で文字間を広げます。 |
| 垂直・水平 | 100%が等倍です。 |
| リガチャ | プロファイル内の設定は設定画面のプレビュー専用です。既定はONです。 |

各項目の白い目はComfontによる上書きが有効、灰色の斜線付きの目は無効です。無効にしても入力値は保存され、再び有効にすると戻ります。色・太字・斜体・縁取りはComfontから上書きしません。

- ↑ / ↓で分類とカスタム範囲を並べ替えられます。Shiftで連続選択、Ctrlで追加・解除、通常クリックで単独選択します。複数行への「適用」は変更した項目だけを更新します。
- 数値はホイールでも変更できます（通常1、Shiftで0.1、Ctrlで10）。単位を変えても数値は自動換算されません。
- `default` は改名・削除できません。中の範囲はすべて削除でき、空のプロファイルでは装飾しません。
- プレビューのガイドは、シアンがグリフ境界、マゼンタが字枠、赤がベースラインです。プレビューは設定確認用で、動画の描画には使いません。

## 絵文字のカラー表示

設定画面のプレビューはCOLR/CPALとSVG-in-OpenTypeをカラー表示します。映像プレビュー／書き出しでは、対応するSVG絵文字とキーキャップを画像へ変換し、通常文字の標準描画へ合成します。キーキャップはCOLR/CPALや単色の字形も対象です。国旗・肌色・ZWJ・キーキャップは1書記素として扱います。追加フィルタや別aux2、本文の編集は不要です。

自動合成は横書きの「標準文字」、表示速度0が対象です。文字毎の個別オブジェクト・自動スクロール・移動座標上の表示はOFF、「リガチャを強制ON」もOFFで使用してください。テキスト入力側の縁取り・影、縦書き、未連携のLua本文には適用しません。フォントに対応字形がない場合や合成できない場合は、標準描画に従います。

comfontの水平・垂直倍率もSVGへ反映します。水平100%・101%・125%・150%・200%と、水平125%／垂直75%で映像プレビュー・AVI出力を確認しました。0.3.3 β初版にあった水平100%超で標準描画へ戻る問題は、`beta-emoji-scale-fix` パッケージで修正しています。フォント一覧の「Comfont Emoji Marker v2」は内部の位置測定用で、選択する必要はありません。対応形式、上限、確認済みの条件は[絵文字の設定と制約](docs/emoji.md)にまとめています。

## 特殊な本文と制限

「描画@comfont」が自動で装飾するのは、**標準テキスト入力が1つで、本文にLuaや未対応の制御タグがないテキストオブジェクト**です。該当しない本文、存在しないプロファイル、効果が無効な場合は通常表示になります。本文に生成した装飾文字列を書き戻すことはありません。

PSDToolKitの字幕には同梱の「合成フォント字幕.object」を使用します。本文内の `settings.id` にキャラクターIDまたは `L3` などのレイヤー指定を設定し、「描画@comfont」でプロファイルを選びます。PSDToolKitは別途必要です。

## 動画出力でのリガチャ

| 「リガチャを強制ON」 | 動画出力の挙動 |
|---|---|
| OFF（初期値） | 通常文字はAviUtl2の標準描画を使い、対応するSVG絵文字とキーキャップはcomfontが合成します。合字はAviUtl2とフォントに従い、プロファイル内のリガチャ設定やアンチエイリアス欄では切り替えられません。 |
| ON（試験機能） | **テキストオブジェクト全体**をComfontのDirectWrite経路で組版し、対応フォントへ任意の合字機能を要求します。プロファイル内のリガチャ設定はこの経路では上書きされます。 |

ONでも、フォントに該当する合字がなければ合字の形は変わりません。ただし、画像化による描画差は生じ得ます。異なるフォント・書式に分かれた文字をまたぐ合字は保証しません。保存本文は変更せず、ZWNJも挿入しません。

ONが使えるのは、Luaを含まない静的な標準テキストで、文字装飾が「標準文字」、表示速度が0の場合です。縁取り・影、文字ごとの個別オブジェクト、自動スクロール、移動座標上の表示、未対応の制御タグ、カラーフォントには対応しません。フォント解決や描画に失敗した場合も**標準描画へ戻るため、強制ONでも合字が適用されないことがあります**。本文は64 KiBまで、文字サイズは1～4096、生成画像は一辺8192ピクセルかつ1677万画素までです。

ONの間だけ「アンチエイリアス」を選べます。「標準」は横方向、「滑らか」は縦横方向に平滑化し、「なし」は平滑化を止めます。大きな文字では前二者の差は輪郭付近に限られます。**ONでは描画結果を一度画像として渡すため、標準描画と輪郭・位置・字間が異なる場合があります。** 品質を優先する作品ではOFFを基本に、必要なオブジェクトで比較してください。

装飾が反映されないときは、プロファイルを「保存」したか、効果に入力した名前が一致しているか、本文が上記の対象条件を満たすかを確認してください。追加したフォントが候補に出ない場合はAviUtl2を再起動してください。

## 保存先と更新時の注意

プロファイルは通常 `C:\ProgramData\aviutl2\compositefont\profiles.json` に保存します。ポータブル構成ではAviUtl2本体横の `data/compositefont/profiles.json` です。追加フォントは同じ `compositefont` フォルダーの `fonts` にTTF / OTF / TTC / OTCファイルを置き、設定画面で保存してAviUtl2を再起動します。プラグインやスクリプトを更新した場合も再起動してください。

詳しい使い方と仕様は[ドキュメント一覧](docs/README.md)から参照できます。設定画面のAPI選択順・互換性・実機確認項目は[描画バックエンド](docs/render-backend.md)を参照してください。ライセンス：[Unicode](resource/unicode/LICENSE.txt) / [Material Icons](resource/material-icons/LICENSE.txt) / [Link](resource/lucide/LICENSE.txt) / [Emoji Marker](resource/emoji-marker-LICENSE.txt)。

## ビルドと配布パッケージ

RustのWindows MSVC環境で、リポジトリのルートから実行します。

```powershell
cargo build -p compositefont-editor-plugin --release --locked
./scripts/package-beta.ps1
```

配布用ZIPは `release/vandojapan.comfont-v0.3.3-beta.au2pkg.zip` です。パッケージスクリプトはCargoからバージョンを読み取り、releaseビルドと同梱DLLのハッシュ確認を行います。依存ライブラリがローカルに揃っている環境で実行してください。

ソースには存在するフィールドが `no field` / `method not found` になる場合は、古いローカル生成物が再利用されていないか確認してください。今回の環境では次の操作で解消しました。

```powershell
cargo clean -p compositefont-core -p compositefont-module-plugin -p compositefont-editor-plugin -p comfont-svg-plugin --release
cargo build --workspace --release --locked
```
