# 絵文字の設定と制約（0.3.3 β）

「絵文字（Unicode 18.0）」プリセットは、絵文字とその構成文字へフォントなどの設定を割り当てます。**対象範囲を網羅することと、すべての絵文字をカラー表示できることは別です。** 表示には、選択フォントがその字形・組み合わせを持ち、描画経路がフォント形式に対応している必要があります。

## 設定方法

1. 合成フォントの設定画面で、「よく使う範囲」から「絵文字（Unicode 18.0）」を追加します。
2. 絵文字に使用するフォントを指定します。映像出力のSVG変換は、Twitter Color EmojiなどのSVG-in-OpenTypeフォントが対象です。
3. プロファイルを保存し、標準テキストに「描画@comfont」を追加して、そのプロファイルを選びます。
4. 「リガチャを強制ON」はOFFにします。

通常文字と絵文字を同じ本文に入力できます。追加フィルタ、別のaux2、本文へのマーカー入力は不要です。設定画面の「適用」は設定プレビューへの反映で、映像へ反映するには「保存」が必要です。

## 表示する場所による違い

| 表示する場所 | comfontの処理と対応範囲 |
|---|---|
| 設定画面のプレビュー | COLR/CPALのレイヤー形式とSVG-in-OpenTypeをカラー描画します。Segoe UI EmojiとTwitter Color Emojiで確認しています。 |
| AviUtl2の映像プレビュー／書き出し | SVG字形を持つ絵文字と、キーキャップの書記素全体を画像へ変換します。キーキャップではCOLR/CPALや単色の字形も使用します。通常文字はAviUtl2が描いた画素を使います。 |
| SVG変換の対象にならない文字 | AviUtl2の標準テキスト描画に従います。設定プレビューと同じ色や字形になるとは限りません。 |

COLR/CPALだけを持つフォントは、キーキャップ以外の絵文字では映像出力の画像変換の対象になりません。ビットマップ形式、COLR v1のペイントツリー、SVGアニメーションはcomfontの独自描画では未対応です。SVGで使える表現はWindowsのDirect2Dに従います。

## 国旗・肌色・ZWJ・キーキャップ

国旗の2つの地域指示記号、肌色付き絵文字、ZWJでつながる絵文字は、1書記素として処理します。たとえば `🇯🇵` を `J` と `P` に分割して描画することはありません。ただし、フォントに対応する合成字形が必要です。

Twitter Color Emojiを使い、映像プレビューとAVI書き出しで `🇯🇵`・`🇺🇸`・`🇬🇧`、肌色・ZWJ、複数行の日本語との混在を確認しています。全Unicode絵文字や、すべてのフォント・シーケンスの映像出力を検証したものではありません。

`0️⃣`～`9️⃣`・`#️⃣`・`*️⃣` の12種類を、国旗と同様に1書記素として扱います。VS16を省略した `1⃣` なども対象です。`🔟` は単独文字（U+1F51F）ですが、同じ画像合成の対象です。VS16省略形はUnicode公式データではunqualifiedとして分類されます。

検証した `TwitterColorEmoji-SVGinOT.ttf` には数字・`#`・`*`・U+20E3のcmapがありませんが、12種類の完成したキーキャップSVGが収録されています。`beta-emoji-keycap-svg-fix` では、実際のフォントファミリがTwitter Color Emojiで、通常の文字対応が欠ける場合に、postテーブルの `31-20e3` などの字形名からグリフIDを取得します。各字形のSVG対応を確認し、設定プレビューと映像出力の共通描画経路で使用します。グリフIDの固定値、フォントファイルの書き換え・再インストールは使いません。 映像出力では、字送りと独立した細いマーカーで位置を測定し、幅の異なるキーキャップを連続させた際のマーカー同士の重なりを避けます。この字形名の規則は他のフォントには適用しません。別バージョンで名前やSVGが欠ける場合は、そのキーキャップに互換処理を適用しません。

利用できる互換SVGがなく、候補フォントが構成文字にも対応しない場合は、書記素全体を下位の一致するカスタム範囲へ渡し、その範囲がなければ数字・記号の分類へ渡します。下位へ渡った場合は、その行のサイズ・縦横倍率を使います。下位フォントでもシーケンス全体をDirectWriteで描画して、Comfont Emoji Markerの配置用スロットへ合成します。COLR/CPALや単色の合成字形も対象です。構成文字の対応だけで、カラーの合成字形を保証するものではありません。フォントの対応を取得できない場合は従来どおり候補を維持し、実際の描画ではDirectWriteのフォールバックが使われる場合があります。

`beta-emoji-keycap-fix` では下位へ渡したキーキャップを標準描画へ戻していたため、結合記号の欠落や重なりが残っていました。`beta-emoji-keycap-render-fix` は、下位フォントのキーキャップも1枚の画像として合成します。自動合成の対象条件を外れる場合や、対応する字形を取得できない場合は標準描画へ戻るため、同じ崩れが生じる可能性があります。

キーキャップを下位フォントでもカラー表示したい場合は、引き継ぎ先の数字・記号の設定にもSegoe UI Emojiなどの対応フォントを指定してください。通常フォントへ引き継いだ場合は、単色のキーキャップになることがあります。

公式の対象集合には数字 `0`～`9`、`#`、`*` も含まれますが、絵文字プリセットはこれらをキーキャップの構成になっている場合だけ対象とします。単独の数字・`#`・`*` は絵文字行のフォントやサイズ・縦横倍率の影響を受けず、下位の設定を使います。保存済み・名前を変更した同じプリセットにも適用します。`©`・`®` などは引き続き絵文字行の対象です。[対象コードポイントと出典](../resource/unicode/README.md#絵文字unicode-180)も参照してください。

## サイズ・縦横倍率

comfontのサイズ、水平・垂直倍率は、SVGをラスタライズする処理にも渡します。倍率に合わせて字送りと配置用の領域も調整します。修正版のreleaseビルドで、水平100%・101%・125%・150%・200%（垂直100%）と、水平125%／垂直75%の映像プレビュー・AVI出力を確認しています。対象フォントはTwitter Color Emoji、文字サイズは32です。全倍率・全サイズ・全フォントの組み合わせを保証するものではありません。設定プレビューではベースライン補正も確認しています。

0.3.3 β初版では、水平100%超で配置用マーカーが後続文字と重なり、通常描画へ戻る場合がありました。`beta-emoji-scale-fix` パッケージでは幅の異なるマーカーと字送り・原点の補正で修正しています。

AviUtl2の「標準描画」にある拡大率・縦横比は、合成したオブジェクト全体にAviUtl2側で適用される設定です。comfontの文字単位の水平・垂直倍率とは別に作用します。

## 自動SVG合成の対象条件

次の条件を満たす標準テキストが対象です。SVG絵文字とキーキャップの自動合成で共通の条件であり、AviUtl2自体のテキスト機能の制約ではありません。

| 項目 | 条件 |
|---|---|
| 入力 | 標準「テキスト」入力が1つ。本文にLua・タブ・未対応／不正な制御タグを含まない |
| 文字装飾 | 「標準文字」。テキスト入力側の縁取り・影、本文タグによる縁取り・影・打消し線は対象外 |
| 文字揃え | 横書き。縦書きは対象外 |
| 表示速度 | 0 |
| 文字毎に個別オブジェクト | OFF |
| 自動スクロール | OFF |
| 移動座標上に表示 | OFF |
| リガチャを強制ON | OFFで使用。全体を画像化する試験経路との併用は保証しない |

ここでいう静的なテキストは、表示速度による文字出しなどを使わない本文を指します。オブジェクト全体の移動・変形まで一律に禁止するものではありません。アニメーション・中間点・すべての外部フィルタの組み合わせは実機で網羅していません。

Luaの `decorate_text` は制御文字列を返すAPIで、SVG画像を合成するAPIではありません。本文内Lua・PSDToolKit字幕object・手動スニペットへ、この自動SVG合成がそのまま適用されるわけではありません。

## 縁取り・影・ぼかしとの組み合わせ

テキスト入力の文字装飾は「標準文字」にし、設定欄の上から **「描画@comfont」→「縁取り」→「ドロップシャドウ」** の順に配置してください。必要な効果だけを追加できます。「ぼかし」も「描画@comfont」の後へ置きます。

Twitter Color Emojiを使った日本語・通常数字・キーキャップ・国旗・ZWJの混在本文で、次をAviUtl2 v2.1.14の映像プレビューとRGB24 AVI出力により確認しています。

| 配置・設定 | 確認結果 |
|---|---|
| 描画@comfont → 縁取り／ドロップシャドウ／ぼかし | 通常文字と絵文字の両方へ効果を適用。国旗・キーキャップ・ZWJの合成を維持 |
| 描画@comfont → 縁取り → ドロップシャドウ | 縁取りと影を併用可能 |
| 縁取り／ドロップシャドウ／ぼかし → 描画@comfont | 前段の効果は再描画で失われる。縁取り・ぼかしでは表示位置のずれも確認 |
| テキスト入力の「縁取り文字」「影付き文字」 | 自動SVG合成の対象外。検証本文では国旗がJPへ戻り、キーキャップ・ZWJも崩れた |

comfontは自身の実行位置でテキスト画像を作り直すため、画像に対する効果は後段へ置く必要があります。上記は標準の3フィルタの静止パラメータでの確認であり、他のプラグインや全パラメータの動作保証ではありません。[検証条件と証跡](validation.md#2026-10-25-縁取り影ぼかしとの組み合わせ)も参照してください。

## 上限と変換できない場合

| 項目 | 内部上限・条件 |
|---|---|
| 本文・装飾後／マーカー置換後の文字列 | 各64 KiB（UTF-8）。入力が短くても、内部タグ追加後に上限へ達することがある |
| SVGへ変換する絵文字 | 1回の合成で256個まで。同じ絵文字の反復も個別に数える |
| 基準の文字サイズ | 1～4096。解決後のサイズ・倍率にも検証がある |
| 水平・垂直倍率 | 内部検証は各1～1000%。組み合わせによっては画像寸法などの上限へ達する |
| 配置用スロット | 字送り2px以上、高さ4px以上 |
| 画像 | 一辺8192px以下、総16,777,216画素以下。通常文字を含む合成画像にも適用 |
| SVG字形画像の合計 | 1回の合成で64 MiBまで |
| 合成結果のキャッシュ | 最大8件、画像合計64 MiBまで |

対象外の設定、上限超過、配置の照合失敗、描画・転送エラーでは、自動SVG合成を行わず通常経路へ戻ります。その結果、国旗が地域記号の文字になったり、カラーが失われたりすることがあります。

描画処理がエラーを返した場合は、AviUtl2のログに `SVG emoji bypass skipped` と理由を最初の1回だけ記録します。対象外設定やSVG字形のない文字など、ログを出さず通常経路を使う場合もあります。表示がおかしいときは、プロファイルの保存、対象条件、使用フォントを確認してください。

## Comfont Emoji Markerとは

`Comfont Emoji Marker v2` は、絵文字の配置位置を測る内部専用の補助フォントです。幅の異なる四角いマーカーと、それぞれ同じ字送りを持つ透明文字を収録しています。一時的に位置を測った後、本来のSVG画像へ置き換えます。修正版では補助フォントもv1からv2へ更新しています。

フォント一覧に出ても手動で選ぶ必要はありません。本文には保存せず、Windowsへのフォントインストールも行いません。AviUtl2のデータ保存先に `compositefont/emoji-marker-v2.ttf` を生成して、ホスト内だけへ登録します。登録に失敗すると自動SVG合成は使えません。
