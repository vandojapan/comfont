# 本文を保持する標準描画経路

2026-10-18、AviUtl2 v2.1.14 / aviutl2-rs 0.50.0で標準描画経路を実証し、製品aux2へ統合しました。統合コードはビルド済みですが、統合後のAviUtl2実機確認はこれからです。

## 結果

「標準本文を直接差し替えるフック」を探す方法から、**標準の入力項目を一時パラメータで呼び直す方法**へ変更すると、本文を保持した装飾が可能でした。

auf2の `FILTER_PROC_VIDEO::exec_effect` は、入力項目を現在のオブジェクトへ実行できます。実際に `"テキスト"` を指定して成功しました。SDKではパラメータはalias形式で渡します。[SDKの関数定義](https://github.com/aviutl2/aviutl2_sdk_mirror/blob/main/include/aviutl2_sdk/filter2.h)に基づく経路です。

## 検証した構成

```text
標準テキスト「原文 ABC ffi」（保存本文は変更しない）
  → 描画@comfont-native-probe.anm2
      プロファイル欄とobj.effectによる委譲だけ
  → aux2に登録した非表示のネイティブフィルタ
      保存原文・プロファイルを参照
      exec_effect("テキスト", 一時的な設定, 現在のオブジェクト)
  → AviUtl2の標準テキスト描画
  → 後続の通常フィルタ
```

anm2側は装飾文字列を組み立てず、本文を書き換えません。aux2は通常のフィルタプラグインを内部登録できるため、別のauf2ファイルを配ることも必須ではありません。mod2単独はスクリプトから呼ばれる関数群で、標準入力を自動で処理する起点にはなりません。

実機での画素一致は固定値の試作で確認しました。製品コードは `profiles.json` を読み、既存のUnicode範囲判定、字形カバレッジ確認、decorateキャッシュを使います。

## 実機で確認したこと

- 標準の参照テキストへ直接 `<s96,Arial><#ff0000>ABC ffi<#><s>` を入力した結果と比較。
- 試験対象の保存本文は `原文 ABC ffi` を保持。
- anm2からaux2内のフィルタを呼び、プロファイル `probe` を読める。
- `exec_effect("テキスト", …)` は成功。
- 結果のサイズは300×112、可視画素が存在し、参照とのRGBA画素列が完全一致。
- 本文保持を再確認し、専用プロジェクトを保存。
- 検証用の画素取得以外に、独自のビットマップ生成・画素アップロード・再サンプリングは行っていない。

証跡は `target/comfont-native-text-verify-20261018/native-text-probe.log` と `native-text-proof.aup2` です。試作ソースは [tools/native-text-probe](../tools/native-text-probe/readme.md) にあります。試作は製品パッケージへ含めません。

比較にはフィルタ内で参照レイヤーをコピーして読み取る方法を使いました。先に試した `rendering_object_video` はこの検証条件でホストのアクセス違反を起こしたため、試作から撤去しました。これを最終描画経路や代替描画方式には使っていません。

## 製品実装

`描画@comfont` はプロファイル名を保持し、`obj.effect("Comfont native text")` でaux2内の非表示フィルタを呼びます。フィルタはプロジェクトaliasから標準テキスト入力の全設定を読み、テキストだけを一時的にdecorateして `exec_effect("テキスト", …)` へ渡します。プロジェクト本文や他の設定値は書き込みません。

Lua本文 (`<? ... ?>`)、未対応制御文字、複数の標準テキスト入力、サイズを安全に読み取れない場合は通常描画へ戻します。不明プロファイル・効果なし・効果無効でもdecorateしません。本文内Luaは再評価しません。PSDToolKit字幕objectと明示Lua連携は別経路のままです。

製品aux2全体をaviutl2-rs 0.50.0へ更新しました。この版の `exec_effect` を使うため、最低ホスト版はv2.1.14です。リガチャ解除用ZWNJは使用せず、通常の標準描画経路ではOpenType機能を切り替えられません。オブジェクト全体を画像化する「リガチャを強制ON」の試験経路と制限は[anm2仕様](anm2-spec.md#リガチャを強制on試験機能)に記載しています。

現段階で確認したのはワークスペースのビルドと、別の固定値試作における実機描画です。統合版で確認が必要な項目は、下記の一覧に残しています。

製品・試作ともにaviutl2-rs 0.50.0を使用します。`exec_effect` が必要なため、製品の最低ホスト版もv2.1.14です。v2.1.14未満ではこの標準描画経路を利用できません。

## 残る検証

- 統合版で保存本文が変化せず、実際のプロファイルがレンダーへ反映されること。
- 日本語・UD新ゴ・オリヤー等の実書体、結合・双方向・縁取り・字間の品質。
- 複数行、座標・中心点、DPI、アニメーション、中間点、描画フィルタ順序。
- 効果OFF・削除、不明プロファイル、保存・再読込、再生・書き出し、負荷。
- 標準入力のOpenType機能を切り替えるAPIは依然未確認。リガチャ解除用ZWNJを再導入しない。

今回の画素一致は固定条件の成立を示すもので、上記の互換性・品質をすべて保証するものではありません。
