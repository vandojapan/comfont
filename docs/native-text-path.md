# 本文を保持する描画経路（0.3.3 β）

「描画@comfont」は保存された本文を読み、描画に使う一時文字列と画像だけを変更します。通常文字はAviUtl2の標準テキスト描画、対応するSVG絵文字はcomfontの画像合成を使います。使用するSDKはaviutl2-rs 0.50.0、必要なホストはAviUtl2 v2.1.14以降です。

## 標準テキストの処理

```text
標準テキストの保存本文・設定
  → 描画@comfont
  → comfont.aux2内の非表示フィルタ「Comfont native text」
  → 選択プロファイルで一時的な制御文字列を生成
  → 通常：exec_effect("テキスト", 一時パラメータ)
     対応するSVG絵文字がある場合：下記の合成処理
  → オブジェクト画像
  → 後続の描画・フィルタ処理
```

プロジェクトaliasから標準テキスト入力の設定を読みます。プロファイルの解決ではUnicode範囲と字形カバレッジを使用し、保存したプロファイルの更新を定期的に読み直します。フォント解決などのホスト呼び出し中はプロファイルのロックを保持しません。

未連携のLua本文、未対応タグ、複数の標準テキスト入力など、自動処理できない条件では通常経路へ戻します。本文内Luaを再評価する処理はありません。

API 17では、本文全体が1つの `<? ... ?>` ブロックであれば、[連携スニペット](lua-api.md#標準テキスト向けの装飾)が装飾前に収集した生成本文を同じ描画経路へ渡せます。Luaモジュールと非表示フィルタがDLL内の有限キャッシュを共有し、オブジェクトID・フレーム・保存本文のalias値が一致する場合だけ採用します。生成元スクリプトの情報がある場合は、現在の効果・コードとも照合します。ホスト呼び出し中はキャッシュのロックを保持しません。

一時パラメータの本文を収集結果へ置き換えてから、プロファイル解決・標準テキスト描画・絵文字合成を実行します。生成本文はaliasとして再復号しません。空本文も処理し、保存したLuaへ書き戻すことはありません。通常文字はAviUtl2が描画し、絵文字だけを画像化します。Lua連携時は「リガチャを強制ON」がONでも全体ラスタライズを呼びません。複数ブロックやブロック外の文字がある保存本文は、収集結果に含まれない文字を失う恐れがあるため対象外です。

## SVG絵文字の合成

API 18のスクリプト制御による明示登録では、元の本文の種類によらず生成全文を採用します。生成元の現在のコードが一致し、効果が「描画@comfont」より前に配置されていることが必要です。本文内Luaの登録は従来の全文ブロック条件を維持します。どちらも同じ標準描画・絵文字合成へ合流し、保存本文とスクリプトは読み取るだけです。

プロファイルを反映した書式から、SVGフォントを使う絵文字を1書記素ずつ抽出します。国旗・肌色・ZWJ・キーキャップを構成する文字は分割しません。絵文字プリセットは単独の数字・`#`・`*` へ適用せず、キーキャップとして一致しない場合や、互換SVGも構成文字の対応もない場合は、下位の一致する範囲／分類へ渡します。

Twitter Color Emoji SVGinOTのキーキャップは、cmapに構成文字がなくてもpostテーブルの既知の字形名からグリフIDを解決します。実際のファミリ名・字形ごとのSVG形式を確認し、IDの固定値は使いません。DirectWriteのinline objectで元のシーケンス全体を1字形として配置し、既存のSVG描画処理へ渡します。この処理は設定プレビューと画像生成で共有し、元の本文・フォントファイルは変更しません。SVGの字送り・描画範囲・原点は別に保持します。

キーキャップは、下位で選んだフォントがCOLR/CPALや単色の字形であっても、DirectWriteで書記素全体を描画し、SVG絵文字と同じ配置用スロットへ合成します。下位フォントを選んだ後に標準描画へ戻して結合記号が分離する問題を避けます。通常の数字にはこの画像変換を適用しません。

1. 絵文字を指定サイズ・水平／垂直倍率でラスタライズし、字送り・原点・ベースラインを取得します。
2. 絵文字を出現ごとに異なる識別色のマーカーへ一時置換し、標準「テキスト」で配置を取得します。幅が1・2・4・8・16・32 emの字形から選び、横倍率を100%以下に保ちます。標準描画の横倍率タグは字送りを変えないため、字間タグで論理幅を別に合わせます。
3. 同じ字送りの透明文字に置換した本文も標準「テキスト」で描画します。
4. マーカー部分を除いた通常文字の画素を照合し、2つの画像の切り出し原点を合わせます。マーカーによって画像幅が1px変わる場合も扱います。
5. 字間補正が字形の前へ半分配分される原点の差を除いて、透明文字の位置へSVG画像を合成し、オブジェクト画像として返します。通常文字の画素は再サンプリングしません。

配置用の `Comfont Emoji Marker v2` は、comfontに埋め込んだ補助フォントです。AviUtl2のデータ保存先へ展開し、ホスト専用のフォントコレクションに登録します。利用者が本文やプロファイルへ設定するフォントではありません。

`exec_effect` がSDK側で更新する画像中心と、aviutl2-rsの `video.param` の保持値は同一とは限りません。配置の照合ではその保持値だけに依存せず、通常文字の画素から原点を求めます。合成に伴う画像寸法の差は中心座標への差分として反映します。

対象条件、寸法・個数・メモリの上限、失敗時の表示とログは[絵文字の設定と制約](emoji.md)を参照してください。すべてのフォント・倍率・アニメーション条件を実機で確認したものではありません。

## リガチャを強制ONにした場合

この試験機能は、絵文字の部分合成とは別に、オブジェクト全体をcomfontのDirectWrite経路で画像化します。通常の標準描画と輪郭・位置・字間が異なる場合があります。対象条件は[anm2仕様](anm2-spec.md#リガチャを強制on試験機能)を参照してください。SVG絵文字の利用時はOFFを使用します。
