# 実装・検証記録

検証日: 2026-10-10～2026-10-11。Rust / aviutl2-rs 0.40.0、Lua、Windows上の作業フォルダー専用AviUtl2 v2.1.2で検証。

現行のanm2契約を [anm2仕様](anm2-spec.md) に固定した。名前変更後の再選択、同名再作成、静的プルダウンの更新手順、本文・設定値を変更しない描画方式を明記する。

## anm2連携の判断

公開SDKに標準テキストの保存本文をanm2から変更するAPIや文字レイアウト前のフックは確認できない。一方、公開Lua APIのobj.putpixeldataを使えば描画画像を差し替えられるため、**本文を変更しない描画時適用**を採用した。anm2はobj.getvalueで本文・標準テキスト設定を読み、aux2が公開するcompositefontモジュールへ自動接続する。モジュールは共有の範囲・フォント解決処理とDirectWriteでBGRA画像を生成し、所有権付きuserdataで同期アップロードの完了まで画像を保持する。

画像は本文・全設定・プロファイルをキーに最大16件／64 MiBでキャッシュする。同じ本文の動画フレームごとにDirectWriteの再描画は行わない。取得失敗、存在しないプロファイル、無装飾・空プロファイル、未対応設定ではホストの元画像を維持する。

2026-10-10公開SDKを追加調査した。実機検証ホストは作業フォルダーのv2.1.2で、当日公開のv2.1.13では未検証。
参照: [公式SDK配布](https://spring-fragrance.mints.ne.jp/aviutl/)、[aviutl2-rs](https://github.com/sevenc-nanashi/aviutl2-rs)、配布本体のlua.txt（obj.getvalue／obj.putpixeldata／select定義）。

| 確認項目 | 結果 |
|---|---|
| anm2追加だけでaux2に接続し、横書き日本語・欧文・数字を装飾 | 実機確認済み。本文への事前組み込みは不要 |
| プロジェクト保存後の本文 | 元fixtureと一致。テキスト=国ABC123\n日本語のままでLuaラッパーなし |
| プロファイル保存→選択肢生成→再起動 | default・aa・無装飾がプルダウンに表示されることを実機確認 |
| プルダウンのdefault適用／無装飾への切替 | フォント変更と元のYu Gothic UIへの復帰を実機確認 |
| anm2効果の無効化 | 元の表示へ戻ることを実機確認 |
| 削除・並べ替え・競合ラベル・区切り文字 | 名前由来ID・保存ラベル照合・競合拒否・サニタイズを実装。生成の単体テスト成功 |
| 複数の同名anm2・動画書き出し | 未実機確認。同名効果の設定取得は最初の有効な効果を参照するため、1つだけ使用 |

プルダウン項目は起動時の静的定義。Luaから動的更新する公開手段は確認できず、エディターの保存でScript/合成フォント.anm2を生成する。項目追加・削除・名前変更後は再起動する。キャッシュ破棄だけでは項目定義は更新されない。本文・プロファイルの補正値は描画キャッシュのキーで追跡する。

現在の描画は字形単位の試験実装。横書き・標準文字装飾のみ対象とする。縦書き・影・縁取り・取り消し線・表示速度・個別文字・スクロール・移動経路・Lua本文・未対応タグ・結合文字／複雑な文字組み／絵文字シーケンスは元画像を維持する。カーニングや合字を含む完全なレイアウト再現は未対応。画像上限4096×4096、本文64 KiB、サイズ1～512。合成フォントは他の画像加工フィルターより前へ置く。

実機fixture: tests/aviutl2/anm2-dropdown-verification.aup2（defaultをプルダウン指定）。tests/aviutl2/anm2-profile-verification.aup2は旧名入力integration-testの互換確認用。旧版の本文ラッパーは復元メニューだけを残し、新規組み込みメニューは廃止した。

## Unicode範囲と互換性

カスタム範囲を先に確認し、最初に一致した範囲で競合解決する。両端は包含、Unicodeスカラー値を端点として検証する。既存7分類は削除状態を別フィールドで保持する。全範囲・分類削除時は無装飾。旧JSONは追加フィールドの既定値で読める。範囲、重複、補助平面、削除・保存再読込み、フォールバックを単体テストで確認。

UIはeframeのOSイベント／再描画要求で動作し、動画フレームのコールバックから起動・更新しない。フォント一覧は画面を開く際に取得、プレビューは変更時だけ生成してテクスチャ／ビットマップをキャッシュする。プレビューは本体のフォント解決・DirectWrite文字計測を共有する。字形単位の比較であり、カーニング・合字・本文制御タグ・オブジェクト配置の完全再現ではない。

### 負荷の予備計測

AviUtl2プロセス全体を約5秒ずつ計測。空プロジェクト、同一起動中。GPUはWindows GPU Engineカウンターの3標本。ホストのバックグラウンド処理を含むためUI単独の性能値でも公平なベンチマークでもなく、優劣の判断には用いない。

| 状態 | CPU時間 / 実測秒 | Working Set MiB | Private MiB | GPU標本 |
|---|---:|---:|---:|---|
| egui待機 | 0.203 / 5.088 | 265.03 | 340.00 | 最大約0.046%、ほか0% |
| eguiを閉じた後 | 1.406 / 5.108 | 234.08 | 293.72 | 0% |
| Win32待機 | 3.297 / 5.105 | 236.80 | 295.75 | 0% |

正式採用前に同一プロジェクト・表示サイズ・操作手順で待機と操作を各30秒以上、開閉を20回以上測定する。再生・出力の処理時間、出力結果、メモリの継続増加、IME確定と候補位置、DPI変更後の入力と配置を確認し、ホストに継続負荷や不具合がないことを採用条件とする。

## プロファイル一覧・詳細プリセットの更新

- 左カラムの見出しを高さ32の1行に限定し、フレームを含めて48以下になることを幅220 / 260 / 360で検証。一覧へ残りの縦幅を渡し、先頭2行がクリップされず表示領域に収まることを確認。
- Unicode 17.0.0の公式346ブロックからサロゲート専用3ブロックを除いた343件を収録。原本との名前・開始終了の一致、重複がないこと、頻用5件の固定順と残りのコードポイント順を検証。
- eguiの範囲追加で漢字・ひらがな・カタカナ・Basic Latin・半角／全角を固定領域に表示。残りを独立した約5行のスクロール領域に表示し、日本語名・英語名・コードポイントを検索可能にした。選択時に端点を入力し、手動編集も可能。
- 通常Win32版にも同じプリセットを提供。先頭プリセットの変更に合わせて初期端点を変更。
- 今回のAviUtl2実機確認はComputer Useの画面取得が `foreground window did not report a process id` で失敗し、ウィンドウ再取得後も同じエラーになったため未実施。実機での表示と検索クリック確認は残る。
